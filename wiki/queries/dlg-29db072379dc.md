## T-2

# Phase 1 Implementation — Work Package 0 (Scaffold)

## Overview

Following the **Phase 1 Implementation Plan** (`wiki/concepts/phase1-implementation-plan.md`), the T-1 execution slice assessment, and platform governance directives, **Work Package 0 (Scaffold)** has been implemented from scratch under TDD-first methodology.

WP0 provides the core application and testing infrastructure for TripleT-Rocketry, establishing asynchronous database session management, structured logging, FastAPI application factory, complete Phase 1 ORM entities, and Alembic migrations.

---

## What Was Implemented

### 1. Packaging and Configuration
- **`pyproject.toml`**: Configured project metadata, strict dependencies (`fastapi`, `uvicorn`, `sqlalchemy[asyncio]`, `asyncpg`, `alembic`, `pydantic`, `pydantic-settings`, `structlog`, `jinja2`, `passlib[argon2]`, `httpx`), Ruff 100-character line limit, and test dependencies (`pytest`, `pytest-asyncio`, `ruff`).
- **`pytest.ini`**: Configured `testpaths = tests` and `pythonpath = .`.
- **`alembic.ini`**: Wired Alembic migrations with Python module paths and logging config.
- **`app/config.py`**: Pydantic `BaseSettings` runtime configuration managing `database_url`, `project_id` (`PROJ-075AA139`), and environment settings.

### 2. Structured Logging
- **`app/logging.py`**: Configured `structlog` pipeline formatting ISO timestamps, stack traces, log levels, and automatic context binding for `trace_id` and `project_id`. No bare `print()` calls are used.

### 3. Asynchronous Database & Session Management
- **`app/db.py`**:
  - `Base`: Declarative base for all SQLAlchemy ORM models.
  - `create_engine_from_url()` & `get_engine()`: Async engine factory using `asyncpg`.
  - `get_session_factory()`: Async session maker with `expire_on_commit=False`.
  - `get_db()`: Async generator dependency yielding per-request `AsyncSession` with automatic rollback on unhandled exceptions.

### 4. Reconciled Phase 1 ORM Models (`app/models/`)
All 9 Phase 1 entities implemented in `app/models/` with foreign-key dependency ordering, UUID primary keys, and docstrings citing relevant wiki entity pages:
- **`enums.py`**: Domain enums (`CertifyingBody`, `CertLevel`, `ImpulseClass` [A–O], `PropellantType`, `CertifyingOrg`, `RocketStatus`, `RecoveryType`, `FlightOutcome`).
- **`base.py` (`AuditMixin`)**: Standard audit columns (`created_at`, `updated_at`, `created_by`, `deleted_at`).
- **`user.py` (`User`)**: Identity and ownership root (`id`, `email`, `display_name`, `password_hash`, `is_active`, `created_at`, `updated_at`).
- **`certification.py` (`Certification`)**: NAR/TRA certification tracking (`user_id`, `certifying_body`, `level`, `cert_number`, `expires_on`, `verified_at`, `override_reason`).
- **`launch_site.py` (`LaunchSite`)**: Launch range specifications (`name`, `latitude`, `longitude`, `max_altitude_agl_m`, `notes`).
- **`motor.py` (`Motor`)**: Catalog performance specifications (`manufacturer`, `model`, `impulse_class`, `total_impulse_ns`, `average_thrust_n`, `max_thrust_n`, `burn_time_s`, `delay_s`, `propellant_type`, `diameter_mm`, `length_mm`, `casing_reusable`, `cert_number`, `certifying_org`, `weight_g`, `UniqueConstraint(manufacturer, model, delay_s)`).
- **`motor_inventory.py` (`MotorInventory`)**: User motor stock and expenditure (`user_id`, `motor_id`, `quantity_on_hand`, `expended_count`, `acquired_on`, `notes`).
- **`rocket.py` (`Rocket` & `RocketConfiguration`)**: Airframe vehicle and versioned configuration snapshots (`version`, `airframe_material`, `fin_count`, `dry_mass_g`, `loaded_mass_g`, `ballast_g`, `cg_mm`, `cp_mm`, `stability_calibers`, `recovery_type`, `parachute_size_mm`, `motor_mount_diameter_mm`, `is_current`, `UniqueConstraint(rocket_id, version)`).
- **`launch_event.py` (`LaunchEvent`)**: Club meet metadata with nullable range officer FKs (`launch_site_id`, `name`, `starts_on`, `ends_on`, `rso_user_id`, `lco_user_id`, `weather_notes`, `pad_count`).
- **`flight.py` (`Flight`)**: Core logbook entity with nullable foreign keys (`rocket_configuration_id`, `motor_id`, `motor_inventory_id`, `launch_site_id`, `launch_event_id`, `flight_number`, `flown_at`, `altitude_agl_m`, `altitude_msl_m`, `max_velocity_mps`, `max_accel_g`, `wind_mps`, `wind_dir_deg`, `temperature_c`, `visibility_m`, `ceiling_m`, `outcome`, `notes`, `media_urls`, `soft_gate_warnings`, `proceeded_despite_warnings`).

### 5. Alembic Migrations (`alembic/`)
- **`alembic/env.py`**: Async migration harness executing migrations against the live database connection.
- **`alembic/versions/p1_001_initial_schema.py`**: Initial schema migration creating enum types and the 7 base tables (`users`, `certifications`, `launch_sites`, `motors`, `rockets`, `rocket_configurations`, `flights`).
- **`alembic/versions/p1_002_inventory_and_events.py`**: Schema expansion migration adding `motor_inventories`, `launch_events`, and wiring foreign keys `motor_inventory_id` and `launch_event_id` into `flights`.

### 6. FastAPI Application Factory (`app/main.py`)
- `create_app()`: Configures application lifespan, request `X-Trace-Id` middleware, and registers:
  - **`GET /health`**: Liveness probe returning application health, project ID, and environment.
  - **`GET /ready`**: Readiness probe executing a `SELECT 1` ping against the database.

### 7. TDD Test Suite (`tests/`)
Written before implementation:
- **`tests/conftest.py`**: Session fixtures and real database transactional rollback fixture (`db_session`) using `AsyncSession` bound to an active transaction that rolls back on test teardown. Never mocks the database.
- **`tests/unit/test_enums.py`**: Unit tests verifying NAR/TRA impulse classes (A–O), certification levels, and flight outcome failure modes.
- **`tests/unit/test_config.py`**: Unit tests verifying setting defaults and override mechanisms.
- **`tests/unit/test_models.py`**: Unit tests verifying model attributes, table names, constraints, and instantiation across all 9 models.
- **`tests/integration/test_health.py`**: Integration tests verifying `/health` and `/ready` HTTP responses and headers via httpx `AsyncClient`.
- **`tests/integration/test_db.py`**: Integration tests verifying PostgreSQL async query execution via the rollback session fixture.
