# Security Policy

TripleT-Rocketry stores personal data about club members, their high-power
rocketry certifications, and a chain-of-custody record for explosive
propellant held under South Australian regulation. Security issues in it are
treated as safety and compliance issues, not only privacy ones.

## Reporting a vulnerability

Report suspected vulnerabilities **privately**. Do not open a public issue and
do not include exploit details in a pull request.

- Open a [GitHub private security advisory](https://github.com/Matt-Thom/TripleT-Rocketry/security/advisories/new) on this repository, or
- email the maintainer at the address on the repository owner's GitHub profile.

Please include: what you found, where (a `path/file.ts:line` reference or a
URL), the steps to reproduce it, and what an attacker gains. A proof of
concept is welcome. Tell us if you intend to disclose publicly and when.

### What to expect

| Stage | Target |
|---|---|
| Acknowledgement | 3 working days |
| Initial assessment and severity | 10 working days |
| Fix for a Critical finding | 24 hours from confirmation |
| Fix for a High finding | 7 days from confirmation |
| Public disclosure | Coordinated with you, after a fix ships |

Severity follows the scale in
[`docs/security-testing-process.md`](docs/security-testing-process.md#8-severity-triage-and-release-blocking).

## Scope

**In scope**: the Cloudflare Worker in `src/`, its D1 schema and migrations,
its deployment configuration in `wrangler.jsonc` and `.github/workflows/`, and
the two deployed hostnames `rocketry.thom.au` and `rocketry-dev.thom.au`.

**Out of scope**:

- Cloudflare's own infrastructure. Report those to Cloudflare.
- The legacy FastAPI service in `app/`, `alembic/` and `tests/`, which is not
  deployed. See [`docs/legacy-fastapi.md`](docs/legacy-fastapi.md).
- Findings that require physical access to a member's device, or that depend
  on a browser or operating system vulnerability rather than on this
  application.
- Reports generated by a scanner with no demonstrated impact.

## Testing this application

If you want to test the deployed service, test **`rocketry-dev.thom.au`
(staging)**, not production. Both hostnames sit behind Cloudflare, whose
[scans and penetration testing policy](https://developers.cloudflare.com/fundamentals/reference/scans-penetration/)
applies: testing is limited to the customer's own assets, some activities need
approval, and denial-of-service simulation of any kind is prohibited. Contact
the maintainer before you begin.

Do not access, modify or exfiltrate data belonging to another member. If a
proof of concept requires it, stop and describe the step instead.

## How this project handles security

Every release passes the nine gates in
[`docs/security-testing-process.md`](docs/security-testing-process.md), which
covers dependency and secret scanning, static analysis, an automated security
regression suite, deployed-configuration verification, an authenticated
dynamic scan against staging, and a manual review by someone other than the
change's author.

The current state of the application against that process, including known
open findings, is recorded in
[`docs/security-baseline-2026-09.md`](docs/security-baseline-2026-09.md).
Every confirmed report becomes a permanent regression test, so a fixed issue
cannot silently return.

## Supported versions

Only the currently deployed release is supported. There are no maintained
older branches.
